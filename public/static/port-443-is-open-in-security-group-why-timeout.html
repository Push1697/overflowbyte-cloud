Port 443 is Open: Security Groups vs Stateless NACLs

Where each sits in the packet path, the ephemeral port trap, and why return traffic vanishes.

November 2026 By Pushpendra Dev OverflowByte Engineering
SCROLL TO EXPLORE
01 — TL;DR & THE MYSTERY

Port 443 is open, EC2 is healthy. Why does it hang?

The security group allows port 443. The target group reports healthy. The web server process is listening. Yet browser requests spin endlessly until timing out.

The culprit is almost always the VPC's Network Access Control List (NACL). Security Groups are stateful firewalls at the ENI; NACLs are stateless firewalls at the subnet boundary. When the client connects to port 443 from a random ephemeral port (e.g. 51432), the server's reply is addressed to port 51432. If your NACL outbound rules do not explicitly permit ephemeral return traffic, the response is dropped silently.

VPC FIREWALL #1
Security Group (SG)
Stateful. Operates at the ENI level. Tracks connections automatically — return traffic is granted without any outbound rule. Allow-only rules.
STATEFUL
VPC FIREWALL #2
Network ACL (NACL)
Stateless. Operates at the subnet boundary. Has zero memory: checks return packets as brand-new traffic. Supports explicit Allow and Deny rules.
STATELESS
THE TRAP
Ephemeral Port Range
Client requests originate from ephemeral ports (1024–65535). Server replies travel back TO those ephemeral ports. NACL outbound must allow them.
EPHEMERAL RANGE
RULE EVALUATION
First Match Wins
NACL rules are numbered. Lowest number wins immediately. If rule 100 allows all and rule 200 denies a bad IP, the deny never fires!

02 — PACKET PATH ARCHITECTURE

Two firewalls, one bidirectional TCP flow

⚡ AWS VPC PACKET INGRESS & EGRESS
🌐 CLIENT
Src: 51432 | Dst: 443
🛡️ NACL (Subnet)
Rule 100 Allow Inbound
💻 EC2 / SG (ENI)
SG Stateful Track
← Return packet: Src: 443 | Dst: 51432 (NACL must permit outbound 1024-65535!)
1. Client SYN Packet Enters IGW
Browser initiates TCP handshake to 203.0.113.10:443 from ephemeral port 51432. Internet Gateway forwards packet through VPC Route Table.
2. Inbound NACL Evaluation
Subnet NACL evaluates inbound rules in numeric order. Rule 100 permits TCP 443 from 0.0.0.0/0. Packet admitted.
3. Inbound Security Group Check
ENI Security Group inspects packet. Port 443 rule matches. Connection tracker establishes state entry: (Client:51432 -> Server:443).
4. Server SYN-ACK Egresses ENI
Web service sends SYN-ACK. Security Group checks connection tracking table: matches existing state, immediately allowed out without consulting outbound SG rules!
5. Outbound NACL Drops Return Packet!
NACL is stateless. It sees an outbound packet destined for port 51432. If only port 443 is allowed outbound, packet hits default Deny (*) and vanishes! Client hangs and times out.
03 — SIDE-BY-SIDE MATRIX

Security Group vs Network ACL

Attribute Security Group Network ACL
Layer of Operation Instance / Elastic Network Interface (ENI) Subnet boundary
State Tracking Stateful (return traffic automatically allowed) Stateless (both directions require explicit rules)
Rule Actions Allow only Allow AND Deny
Evaluation Order All rules evaluated together Numbered, lowest number first (first match wins)
Cross-Referencing Can reference other Security Groups & Prefix Lists CIDR IP blocks only
Default Behavior (Custom) Inbound blocked, outbound open Denies all traffic inbound and outbound
04 — CLI REMEDIATION

Fix the NACL outbound rule via AWS CLI

aws-cli — create-network-acl-entry
$ aws ec2 describe-network-acls --network-acl-ids acl-0123456789abcdef0
"Entries": [ { "RuleNumber": 100, "Protocol": "6", "RuleAction": "allow", "Egress": true, "PortRange": { "From": 443, "To": 443 } } ]
# ERROR: Outbound only allows 443, dropping ephemeral return traffic (1024-65535)!
$ aws ec2 create-network-acl-entry \ --network-acl-id acl-0123456789abcdef0 \ --egress --rule-number 110 \ --protocol tcp --port-range From=1024,To=65535 \ --cidr-block 0.0.0.0/0 --rule-action allow
✓ Rule 110 created successfully
$ curl -Iv https://app.example.com
HTTP/2 200 OK — Connected in 18ms!
05 — SRE BEST PRACTICES

Rules for bulletproof VPC security design

Always Permit Ephemeral Ports Outbound on NACLs
Add an egress rule permitting TCP 1024–65535 to 0.0.0.0/0 so return packets for HTTP, HTTPS, and API calls never drop.
Number NACL Rules in Increments of 100
Space out rule numbers (100, 200, 300) so emergency CIDR block rules (e.g. Rule 90 DENY) can be inserted immediately before allows.
Use Security Group Chaining in Multi-Tier Apps
Do not hardcode IPs. Let sg-app trust sg-alb, and let sg-db trust sg-app.
