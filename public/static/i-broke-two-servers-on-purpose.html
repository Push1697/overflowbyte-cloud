03 — TRIAGE WORKFLOW

How to isolate the saboteur timer that undoes repairs

1. Observe the Symptom: Repaired Fault Recurs
You restored DNS or unblocked a firewall port, but 3 minutes later the service breaks again. Something on the host is executing on a schedule.
2. Query All Active Timers
Run systemctl list-timers --all. Look for suspicious units with recent trigger times or unrecognized names.
3. Inspect Unit Definition and Script Target
Run systemctl cat <unit> to reveal the target ExecStart binary. Inspect the script to verify it is the saboteur.
4. Eradicate and Reload
Stop and disable the timer and service. Delete both unit files and the payload script. Run systemctl daemon-reload.
04 — DIAGNOSTIC TERMINAL

Investigating du vs df mismatch & deleted file handles

bash — storage triage: du vs df
$ df -h /var
/dev/mapper/rhel-var 10G 9.8G 200M 98% /var # DISK FULL!
$ du -sh /var
1.2G /var # du only sees 1.2G! Where is the other 8.6G?
$ lsof +L1 /var | grep '(deleted)'
httpd 1402 apache 3w REG 253,2 8858372096 0 /var/log/httpd/access.log (deleted)
$ systemctl reload httpd # Releases unlinked file descriptor
$ df -h /var
/dev/mapper/rhel-var 10G 1.2G 8.8G 12% /var # Space freed!
